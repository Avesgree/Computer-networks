
# Процессы и потоки в операционных системах

Процессы и потоки — это базовые абстракции операционных систем, предназначенные для эффективного распределения ресурсов и распараллеливания вычислений.

## 1. Иерархия вычислительных единиц

В современных ОС выделяют четыре уровня управления задачами:

| Название | Описание | Примечания |
| :--- | :--- | :--- |
| **Задание (Job)** | Коллекция процессов, у которых общие квоты и лимиты. | Используется редко. |
| **Процесс (Process)** | Программа в стадии выполнения. Является контейнером для ресурсов. | Заявка на все ресурсы, кроме CPU. |
| **Поток (Thread)** | Единица планирования для ядра ОС, которой выделяется процессорное время. | В простейшем случае процесс состоит из 1 потока. |
| **Волокно (Fiber)** | «Легкий» поток, управляемый полностью в пространстве пользователя. | Используется редко. |

## 2. Разделение элементов внутри процесса

Потоки, запущенные внутри одного процесса, делят общую память, но имеют независимые структуры для выполнения своего кода:

| Элементы, совместно используемые всеми потоками | Индивидуальные элементы каждого потока |
| :--- | :--- |
| • Адресное пространство<br>• Глобальные переменные<br>• Открытые файлы<br>• Дочерние процессы<br>• Сигналы и их обработчики<br>• Информация об использовании ресурсов | • Счетчик команд (Program Counter)<br>• Регистры процессора<br>• Стек<br>• Текущее состояние |

## 3. Жизненный цикл и состояния потоков

Поток создается, а затем циклически переключается между тремя основными состояниями:
1. **Готовность** — поток создан, находится в очереди и ждет выделения процессора.
2. **Выполнение** — поток выбран планировщиком и исполняется на процессоре.
3. **Ожидание** — поток заблокирован из-за системного вызова или ожидания ввода/вывода.

### Моменты перепланирования (когда вмешивается ОС):
* Закончился квант времени, отведенный активной задаче.
* Задача сделала блокирующий системный вызов (запрос ввода/вывода, доступ к занятому ресурсу).
* Задача освободила ресурс, который ждали другие потоки.
* Периферийное устройство завершило операцию ввода/вывода.
* Произошло внутреннее прерывание (ошибка в коде задачи).

## 4. Алгоритмы планирования

Подходы к распределению процессорного времени зависят от типа операционной системы:

* **В интерактивных системах:**
  * *Циклическое (квантование)* — каждому потоку дается фиксированное время.
  * *Приоритетное* — первыми выполняются наиболее важные потоки.
  * *Гарантированное* — ОС отслеживает баланс времени, распределяя его поровну между пользователями.
  * *Лотерейное* — ресурсы разыгрываются случайно на основе выданных "билетов".
  * *Справедливое* — учитывает, кто является владельцем процесса.
* **В системах реального времени:**
  * Главный критерий — **реактивность** (способность жестко выдерживать заданные интервалы).
  * *Алгоритм Лью - Лейланда* — классический подход, где задача с самым коротким периодом получает наивысший приоритет.

## 5. Синхронизация и межпроцессное взаимодействие (IPC)

Когда несколько потоков одновременно работают с общими переменными, возникает опасность **эффекта гонок (взаимных состязаний)**. Из-за этого результат программы становится непредсказуемым.

### Ключевые понятия и инструменты:
* **Критическая секция** — часть программы, работающая с общими критическими данными. В ней в каждый момент времени должен находиться только один поток.
* **Способы взаимного исключения:** запрет прерываний, неделимые блокирующие переменные, мьютексы и семафоры Дейкстры (с операциями `P` и `V`).
* **Механизмы обмена данными (IPC):** каналы (pipes), очереди сообщений, почтовые ящики, сокеты и разделяемая память.

## 6. Проблема взаимных блокировок (Deadlocks)

**Взаимная блокировка (тупик, дедлок)** — ситуация, когда несколько процессов блокируют друг друга, удерживая одни ресурсы и бесконечно ожидая доступа к другим.

### 4 необходимых условия возникновения тупика (Условия Коффмана):
1. **Взаимное исключение** — ресурс занят одним процессом или свободен.
2. **Удержание и ожидание** — процесс, удерживая один ресурс, может просить новые.
3. **Отсутствие принудительной выгрузки** — у процесса нельзя насильно отобрать ресурс.
4. **Циклическое ожидание** — образуется замкнутая цепь процессов, где каждый ждет соседа.

### Стратегии борьбы с тупиками:
* **Обнаружение и устранение:** ОС строит графы распределения ресурсов и ищет в них циклы. При обнаружении тупика один из процессов принудительно завершается или откатывается назад.
* **Динамическое избежание:** расчет траектории ресурсов и проверка каждого шага на безопасность. Используется *Алгоритм банкира Дейкстры* для одного или нескольких видов ресурсов.
* **Предотвращение:** проектирование системы так, чтобы нарушить хотя бы одно из четырех условий Коффмана (например, присвоение ресурсам жесткого линейного порядка запроса).
