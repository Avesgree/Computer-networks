HTTP (HyperText Transfer Protocol) — это протокол передачи гипертекста, предназначенный для обмена данными в веб-среде между клиентом и сервером с помощью цикла «запрос-ответ».

Сетевая архитектура и безопасность

* Клиент-серверная модель
  Архитектурный шаблон взаимодействия, при котором инициатором выступает клиент (отправляет запросы), а сервер обрабатывает их и возвращает результат (ответы).

* Протокол HTTPS (HTTP + SSL/TLS)
  Защищенная версия HTTP, шифрующая передаваемый трафик. Она гарантирует конфиденциальность данных и аутентификацию (проверку подлинности) сервера. По умолчанию использует порт 443 вместо стандартного 80.

* Идемпотентность
  Свойство операции, гарантирующее, что повторные вызовы одного и того же запроса изменят состояние сервера точно так же, как и один-единственный вызов. Примерами являются методы GET, PUT и DELETE.

Структурный разбор HTTP-запроса

На примере метода создания пользователя (POST) запрос делится на три ключевые части:

1. Стартовая строка:
   * Метод: POST (указывает на создание нового ресурса).
   * Путь: /api/users (целевой эндпоинт на сервере).
   * Версия протокола: HTTP/1.1.

2. Заголовки (Метаданные):
   * Authorization: Передает Bearer-токен для проверки прав доступа клиента.
   * Content-Type: Имеет значение application/json, сообщая серверу, что данные в теле представлены в формате JSON.

3. Тело запроса:
   Отделено от заголовков пустой строкой и содержит полезную нагрузку:
   {
     "name": "Иван",
     "email": "ivan@mail.com"
   }

Структурный разбор HTTP-ответа

Ответ сервера на успешную операцию содержит следующие элементы:

1. Статус-код:
   201 Created — подтверждает, что новый ресурс был успешно создан в системе.

2. Заголовки:
   Location — возвращает точный URI созданного объекта (/api/users/42) для последующего обращения к нему.

3. Тело ответа:
   Передает актуальное состояние созданного объекта (включая присвоенный системой ID):
   {
     "id": 42,
     "name": "Иван",
     "email": "ivan@mail.com"
   }
